# Configuration

[← Documentation](README.md)

Everything is set through environment variables. No secret is written to a versioned file:
`.env` is ignored by Git. The variables specific to the local binary are in
[Local usage](LOCAL.md#settings).

## HTTP server variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `PARFUMO_MCP_MASTER_KEY` | — (required for `serve`) | AES-256-GCM key, 32 bytes in base64. Generated by `parfumo-mcp-server keygen`. Never stored in the database |
| `PARFUMO_MCP_MASTER_KEY_FILE` | — | Alternative: path of a file holding the key (Docker secret) |
| `PARFUMO_MCP_DOMAIN` | — | Public domain name, used by `docker-compose.yml` and Caddy |
| `PARFUMO_MCP_PUBLIC_URL` | `http://localhost:8080` | Public URL of the server. Set to `https://<domain>` by `docker-compose.yml`. Used for OAuth metadata and for checking the `Host` and `Origin` headers |
| `PARFUMO_MCP_BIND` | `0.0.0.0:8080` | Listening address inside the container |
| `PARFUMO_MCP_DB` | `/data/parfumo-mcp.db` | SQLite file, on the Docker volume `parfumo-data` |
| `PARFUMO_BASE_URL` | `https://www.parfumo.com` | Parfumo domain |
| `PARFUMO_MCP_USER_MIN_INTERVAL_MS` | `1000` | Minimum interval between two requests of one user to Parfumo (never below 1000) |
| `PARFUMO_MCP_USER_JITTER_MS` | `400` | Maximum random delay added to each request |
| `PARFUMO_MCP_GLOBAL_RPS` | `2` | Requests per second, all users together (2 at most) |
| `PARFUMO_MCP_ACCESS_TOKEN_TTL_SECS` | `3600` | Lifetime of an OAuth access token (clamped to 1 minute – 1 day) |
| `PARFUMO_MCP_REFRESH_TOKEN_TTL_SECS` | `2592000` | Lifetime of a refresh token (30 days, single use; clamped to 1 hour – 90 days) |
| `PARFUMO_MCP_PUBLIC_WRITES` | `false` | `true` allows writes that other members can see to be really sent. See below |
| `PARFUMO_MCP_PUBLIC_WRITE_CAPS` | defaults below | Daily caps on public writes, per tool and per user |
| `PARFUMO_MCP_WRITE_RECIPIENTS` | empty (no restriction) | Parfumo nicknames the server accepts to write to |
| `PARFUMO_MCP_CANARY_HOUR` | `4` | UTC hour (0–23) of the daily canary. `off` disables it |
| `PARFUMO_MCP_CANARY_USER` | empty (public pages only) | Server user whose linked Parfumo account — a test account — the canary also reads |
| `PARFUMO_MCP_CANARY_WEBHOOK` | empty | URL that receives a JSON alert when the canary is not `ok`, and again when it recovers (Slack and Discord formats) |

## Public writes

A public write is one that another Parfumo member can see: a wear, a rating, a
classification, a review, a statement, a private message, a follow, a wall post, a forum
post, a blog article, a Souk entry, a profile change. Three safeguards apply, in this order.

1. **Lock.** Without `PARFUMO_MCP_PUBLIC_WRITES=true`, these tools answer as in `dry_run`:
   they show the requests they would send and send nothing.
2. **Recipients.** If `PARFUMO_MCP_WRITE_RECIPIENTS` is set (comma-separated nicknames),
   only those members can receive a message, a wall post or a follow. Anyone else is refused
   before any request is made.
3. **Daily cap, per tool and per user.** Defaults:

   | Tool | Per day |
   | --- | --- |
   | `parfumo_send_message` | 20 |
   | `parfumo_forum_post` | 10 |
   | `parfumo_write_review`, `parfumo_write_statement` | 10 each |
   | `parfumo_wall`, `parfumo_souk_manage_offer` | 10 each |
   | `parfumo_blog` | 5 |
   | `parfumo_manage_follow` | 30 |
   | `parfumo_update_profile`, `parfumo_log_wear` | 20 each |
   | `parfumo_rate_perfume`, `parfumo_classify_perfume` | 100 each |

   Override them with `PARFUMO_MCP_PUBLIC_WRITE_CAPS`, as comma-separated `tool=number`
   pairs, for example `parfumo_send_message=5,parfumo_blog=0`. Tools not listed keep their
   default; `0` forbids a tool's public writes. An unknown name or an invalid number
   prevents startup.

A cap counts calls that really send something: a dry run, or a call that changes nothing,
costs nothing. The counter is stored in the database, so it survives a restart, and resets
at 00:00 UTC. Past the cap the tool returns `rate_limited` with the waiting time and sends
nothing. `parfumo_session_status` gives what is left for the day.

**Text.** Parfumo forbids AI-generated text and restricts or deletes accounts that publish
it. Tools that send text say so to the assistant: it passes on the user's words, it does not
write them. The server cannot verify who wrote a text.

## Fixed behaviour

These are not configurable.

| | |
| --- | --- |
| Cache | 24 h for perfume, brand, perfumer and note pages; 1 h for searches and rankings; none for account data |
| Audit log | Every tool call: tool, target, outcome, duration and number of writes really sent to Parfumo. Kept 90 days |
| `User-Agent` | Fixed and honest; no rotating browser imitation |
| Captcha, Cloudflare challenge | Never solved or bypassed: the tool returns `captcha_required` |
